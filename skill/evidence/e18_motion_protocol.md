## 启动与接线

FPGA启动5秒后沿用原有逻辑自动开放控制；不向电机发送上电回零、保存零点或启动上移指令。两台驱动器自行回零，5秒计时不证明实际回零完成。底座上电目标45°，夹爪上电目标35°（张开）。

接线沿用现有XDC：PC RX/TX为T15/T14（J20-7/8），电机1 TX/RX为R14/P14（J20-3/4），电机2 TX/RX为U15/U14（J20-11/12），夹爪P19（J20-13），底座N18（J20-14）。外设共地，串口为3.3 V TTL。

电机地址分别01、02，各占一组UART；电机及PC串口均为115200、8N1。自动移动使用Emm的0xFD绝对位置模式01，方向0=CW、1=CCW，尾字节0x6B。净脉冲是相对于同一驱动回零位置的绝对目标，每圈3200脉冲。实际位置0x36反馈为每圈65536单位，仅用于反馈，不能直接当作运动脉冲。原有手动M1/M2仍使用相对实际位置模式02。

## 串口操作

发送ASCII文本，每条以CR、LF或CRLF结束。坐标单位厘米，支持正负号及最多两位小数，格式如`(1.25,-2.50)`；数字必须有整数部分，小数点后必须有数字。数值编码范围为每轴±1000000.00厘米，超出编码范围或格式错误回复`ERR SYNTAX`，不动作。这个范围仅为解析器表示范围，不代表机械可达范围。

| 指令 | 完成应答 | 行为 |
| --- | --- | --- |
| `(x,y)` | `0 OK` | 前往估算的抓取点并合爪 |
| `1`至`6` | 对应的`1 OK`至`6 OK` | 搬运到该组下一子坐标并松爪 |
| `OVER` | `OVER OK` | 返回0.0、松爪并清零所有放置计数 |
| `STOP` | `OK STOP` | 中断流程，停止两轴并锁定控制 |
| `READY` | `OK READY` | 启动等待结束后解除停止锁定，不移动 |
| `STATUS` | `STATUS` 加6个数值 | 动作期间也可查询解锁状态、坐标掩码、舵机目标、速度及加速度 |
| `PROGRESS` | `PROGRESS` 加6个数值 | 查询当前步骤与最近故障，不产生运动 |

一次正常交互如下，每次都等应答后再发下一条：

```text
发送 (1.25,-2.50)
接收 0 OK
发送 2
接收 2 OK
发送 (8,4)
接收 0 OK
发送 3
接收 3 OK
发送 OVER
接收 OVER OK
```

未抓取时直接发送组号，返回`ERR EXPECT_PICK`。抓取后再次发送坐标或手动运动指令，返回`ERR EXPECT_DROP`，等待放置组号或OVER。执行动作期间不排队其他动作；忙请求合并为一条`ERR BUSY`，在当前应答发送完成后返回。STOP可打断动作，不受此规则限制。`STATUS`、`PROGRESS`可在动作期间读取；查询与完成回包逐行完整发送，连续查询只保留最新的待发快照。不要连续发送动作命令，也不要把查询回包当成动作完成。

原有STATUS、READ、DIAG、SPEED、ACC、逐轴示教等命令保留。自动流程默认沿用60 RPM、加速度档位100；显式SPEED/ACC仍可修改后续运动参数。夹爪`GRIP`命令只接受0–35°：0°闭合，35°张开。

也可关闭占用串口的串口助手后使用`python tools/claw_console.py send --port COM5 "(1.25,-2.50)"`发送，COM5替换为实际端口。客户端对自动动作等待上限为200秒，涵盖多段电机运动；普通指令仍等待65秒。

## 动作顺序

每轮抓取均依次执行：电机2到绝对−1800脉冲 → 底座到目标角度 → 电机1到目标净脉冲 → 电机2到1200脉冲 → 夹爪到0°（闭合） → 回复`0 OK`。负方向为向上；−1800是固定目标，与上一轮的放置高度无关。

每轮放置均依次执行：电机2到绝对−1800 → 电机1到放置目标 → 底座到放置角度 → 电机2到该点的2500脉冲 → 夹爪到35°（张开） → 回复组号OK。

1–6组各自计数，从`.1`开始，依次`.1 → .2 → .3 → .4 → .1`循环。只有松爪等待结束、成功应答发送完成后，才推进该组计数。STOP或电机错误不推进计数。计数为运行时状态，FPGA重新配置或复位后从`.1`开始。

OVER执行：电机2到−1800 → 电机1到1100 → 底座到135° → 电机2到1200 → 夹爪到35°（张开） → 回复`OVER OK`；应答完成后所有组下一次均使用`.1`。OVER不会发送电机回零指令。

两轴每次运动都先检查驱动保护及使能状态，收到运动接受应答后每50 ms轮询到位标志，连续两次到位并读回实际位置后才继续。单次电机通信超时200 ms，从整条请求发送完毕开始计时，每段电机运动超时60秒。只读请求（0x1F/22/36/3A/3B）遇到超时或坏尾字节时最多重试2次，共3次；重试前丢弃残帧并等待至少2个字符的空闲，持续噪声也会超时退出。运动、停止、回零和保存零点命令均不自动重发。未读到有效位置不会下降。保护、重试用尽或运动超时将中止流程并尝试停止两轴，不发送该轮成功应答；若停止也无应答，最终错误为`ERR STOP_LINK`。

### 停在坐标上空时查询

发送`PROGRESS`（ASCII，带换行）读取：

```text
PROGRESS <当前状态> <自动步骤> <当前轴> <本段运动已用毫秒> <最近故障状态> <最近故障码>
```

当前轴0代表电机1，1代表电机2。抓取自动步骤0为抬升、1为底座旋转、2为平移、3为下降、4为合爪；空闲时步骤和轴保留上次值。常见状态0为空闲、4为等待运动应答、5–7为轮询到位、9为等待位置读回、10为等待舵机、13–14为停止处理、34为等待完成回包发送。最近故障状态和故障码在复位后为0，发生异常后保留至下次异常或复位；`READY`不会清除它们。

故障码1为驱动拒绝命令，2为通信超时，3为坏尾字节，4为非法位置反馈，5为通信被取消，6为整段运动超时。保护等由控制器判定的故障还需结合`ERR ...`文字判断；故障码0本身不表示本轮成功。`ERR STOP_LINK`可能覆盖最初的错误文字，`PROGRESS`仍保留触发停止时的状态和错误码。收到错误后先检查机械位置和通信，再决定`READY`及后续操作；不要重复发送上一条抓取命令来试探。

底座和夹爪按每20 ms变化1°到达目标；底座再等1000 ms、夹爪再等500 ms才继续。舵机是开环PWM控制，这些等待不代表测得实际机械到位。STOP冻结当前PWM角度目标，不会断开舵机电源。异常中断后应检查机械状态再READY；必要时用OVER结束当前搬运并重置计数。

## 五点插值与外推

自动坐标源是`calibration/coordinate_table.json`，固化表为`rtl/automatic_coordinates.vh`，使用净脉冲；与示教表`coordinate_defaults.vh`中的编码器原始反馈单位不同。SAVE/LIST及导出工具操作的是示教表，不会自动改写自动抓放表。Python测试逐项核对全部29个自动坐标与JSON一致。

五个抓取点为：

| 标签 | 平面位置（厘米） | 电机1净脉冲 | 电机2净脉冲 | 底座角度 |
| --- | --- | --- | --- | --- |
| 0.0 | (0,0) | 1100 | 1200 | 135° |
| 0.1 | (−5,5) | 200 | 1200 | 100° |
| 0.2 | (−5,−5) | 2500 | 1200 | 117° |
| 0.3 | (5,5) | 200 | 1200 | 170° |
| 0.4 | (5,−5) | 2500 | 1200 | 153° |

中心与相邻两角组成上、下、左、右四个三角形。范围内按所在三角形做仿射插值；范围外按同一方向区域的仿射平面外推，不吸附到标定点或边界。五个标定点严格复现原值，四个区域在共享边界连续。五点高度相同，因此抓取高度始终1200。

坐标按0.01厘米定点表示；加权计算保留64位中间值，最后四舍五入到整脉冲和整度。计算先限幅再缩小除法位宽，分时钟周期完成，避免64位单周期除法成为长路径。计算结果分别限制电机1到0–4000、底座到0–270°，仍继续执行动作。这里是两个执行器目标分别限幅，不承诺是实际平面欧氏距离最近的可达点。

例如`(8,4)`得到电机1为580脉冲、底座184°、电机2为1200脉冲。超限示例：`(0,20)`电机1限制为0，`(0,-20)`限制为4000。五点插值、外推及整度舵机控制都无法保证毫米级实际精度；实际误差需要现场使用独立测试点测量。
